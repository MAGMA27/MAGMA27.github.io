# SFT

## Why do we need SFT?

By training on a large amount of text, a model can become a general-purpose model through token-by-token learning. This stage is pre-training: it internalizes knowledge and capabilities, but the model still needs to be taught how to communicate. For example, teaching it to output answers in a specified format or to communicate in a friendly way must happen at this stage, which is called post-training or fine-tuning.

## How is SFT done?

Supervised Fine-Tuning (SFT) is the most natural approach. It continues the pre-training strategy: humans select or write specific data, and the model learns from it token by token in a supervised manner, much like it did during pre-training. For example, this method can be used to teach the model to produce chain-of-thought or output in JSON format.

## What are its shortcomings?

1. It relies heavily on manually labeled data. A large amount of high-quality, diverse, task-specific labeled data is needed, which is expensive to obtain and easily influenced by annotator bias. If the labeled data contains noise, inconsistencies, or errors, SFT will learn those errors directly, leading to unreliable model outputs. Correcting errors usually requires relabeling or cleaning the data, which is costly.
2. Its generalization ability is limited. The model is effectively still "learning how to speak". If the time, domain, or user population changes, its performance may decline significantly; the data must be continuously updated or the model must be fine-tuned again to maintain its performance.
3. Catastrophic forgetting: when a model is heavily fine-tuned toward a target, it may over-adapt to the new task and forget the general knowledge learned during pre-training.
4. Insufficient output diversity: because the training objective is to maximize the probability of the labeled output for a given input, the model tends to produce fixed, template-like replies that lack creativity and diversity. This can limit performance on tasks requiring open-ended generation, such as creative writing and dialogue.

# GRPO

## Why do we need reinforcement learning?

1. Reinforcement learning reduces the need for labeled data.
2. In SFT, every token's input during training is a true prefix (teacher forcing), whereas during inference the model sees tokens generated by itself. This inconsistency is called exposure bias and can cause errors to accumulate. During RL training, the model generates a complete sequence itself and then updates the policy based on a reward signal. This is closer to the actual distribution seen during inference, so it can reduce exposure bias and improve generation quality.
3. It can flexibly incorporate complex, non-differentiable objectives. Human preferences often include multiple dimensions, such as helpfulness, safety, and interestingness, which are difficult to express as a simple loss function. A reward model is essentially a learned black-box scorer whose gradient cannot be passed directly to the generative model because generation is a discrete sampling process. Reinforcement learning methods such as policy gradients do not require the reward function to be differentiable; they only require a reward value and can update the model through algorithms such as REINFORCE or PPO.

## How is it done?

Reinforcement learning is particularly suitable for tasks such as mathematics and code that have clear evaluation criteria. In reinforcement learning, the LLM serves as the policy, each text sampled according to the policy is treated as an action, and a complete text sequence is a rollout.

The old model samples multiple trajectories for the same question and treats them as a group. It then calculates the relative advantage: how the reward obtained by each trajectory compares with the group average. This determines whether the probability of that trajectory should be reinforced or suppressed.

### The "loss" function

The GRPO method can be traced back to Policy Gradient, whose goal is to find an optimal policy that maximizes the return from the environment. Define the objective as $J(\theta) = E_{s_0}[V^{\pi_{\theta}}(s0)]$, then differentiate the objective with respect to the policy parameters, obtain the gradient, and use gradient ascent to find the optimal policy. Therefore, GRPO does not actually define a loss function; it only borrows automatic differentiation to perform gradient updates. The final GRPO objective is:

$$J_{\text{GRPO-Clip}}(\theta) = \mathbb{E}_{q \sim \mathcal{D},\; \{o^{(i)}\}_{i=1}^{G} \sim \pi_{\theta}(\cdot \mid q)} \left[ \frac{1}{G} \sum_{i=1}^{G} \frac{1}{|o^{(i)}|} \sum_{t=1}^{|o^{(i)}|} \min \left( \frac{\pi_{\theta}(o^{(i)}_t \mid q, o^{(i)}_{<t})}{\pi_{\theta_{\text{old}}}(o^{(i)}_t \mid q, o^{(i)}_{<t})} A^{(i)},\; \operatorname{clip}\!\left( \frac{\pi_{\theta}(o^{(i)}_t \mid q, o^{(i)}_{<t})}{\pi_{\theta_{\text{old}}}(o^{(i)}_t \mid q, o^{(i)}_{<t})},\; 1-\varepsilon,\; 1+\varepsilon \right) A^{(i)} \right) \right]$$

The Clip component is inherited from TRPO/PPO. It clips the ratio during importance sampling to ensure that each policy update does not destroy behavior learned previously, avoiding a performance collapse caused by taking too large a step at once.

### Sample efficiency

Training with data generated entirely by the current policy is called on-policy learning. Its advantage is that every training step uses data generated by the policy itself, so the gradient estimate is unbiased and stable. However, the data is discarded after use and cannot be reused, resulting in low sample efficiency. An off-policy method can also be used: data generated once is used for several rounds of training, so later rounds use data that they did not generate themselves. This improves sample efficiency, but importance sampling is needed to correct the difference in data distributions, which can introduce high variance and numerical instability; ratio clipping must be introduced to stabilize training.

### Gradient accumulation

When the batch size is large enough that the full batch cannot fit into memory at once, gradient accumulation can be used. Specifically, split the batch into smaller microbatches, use only one microbatch at a time, and divide the loss by (microbatch size / batch size) to determine this step's proportion of the total gradient. Only after all the data in one batch has been used is an update performed; the gradients are not cleared in between.

Why not accumulate only the loss and call backward once at the end? Each loss determines a reference for where the model should move next and also depends on the input parameters. What really matters is the gradient, which determines where the model parameters should move next. Passing a loss and passing a gradient are fundamentally different: a loss is a scalar, while a gradient is a high-dimensional tensor. Passing the loss is equivalent to compressing the information in a high-dimensional tensor into a scalar; calling backward only at the final step cannot recover the gradient direction from each intermediate step.

## What are its shortcomings?

1. It is sensitive to the quality of samples within a group. If the samples in a group are too similar, for example because the reward model cannot distinguish good from bad, or differ too drastically, for example because of an extremely low-scoring sample, the relative-advantage estimate may be biased and policy updates may become unstable.
2. It amplifies reward-model flaws. If the reward model has a systematic bias, such as preferring certain patterns or being sensitive to length, that bias is amplified by within-group comparisons. The model then learns to exploit weaknesses in the reward model instead of genuinely matching human preferences.
3. It poses training-stability challenges. Because advantage estimates are based entirely on within-group statistics such as the mean and standard deviation, sharp changes in the reward distribution within a group can cause the scale of the advantages to change abruptly, making the policy-gradient step size unstable.
4. If every output in a group is wrong or every output is correct, the relative advantage within the group is zero and cannot provide a useful learning signal.
5. The loss is averaged within each sample first and then averaged across samples. This gives every sample the same weight, which is unfair to long sequences.

## Experimental results

The training parameters were set as follows:

```python
config = {
        "n_grpo_steps": 200,
        "learning_rate": 1e-5,
        "advantage_eps": 1e-6,
        "rollout_batch_size": 256,
        "group_size": 8,
        "sampling_temperature": 1.0,
        "sampling_min_tokens": 4, # As in Expiter, disallow empty string responses
        "sampling_max_tokens": 1024,
        "epochs_per_rollout_batch": 1, # On-policy
        "train_batch_size": 256, # On-policy
        "gradient_accumulation_steps": 128, # microbatch size is 2, will fit on H100
        "gpu_memory_utilization": 0.8,
        "loss_type": "reinforce_with_baseline",
        "use_std_normalization": True,
    }
```

I trained for 200 steps using the SFT dataset in `data`, splitting the total batch size of 256 into microbatches of 2 according to the gradient accumulation method. The step loss is shown below. Because the loss here actually represents the policy-gradient objective for each group and only indicates the update direction, it oscillates.

I evaluated the GRPO results on 5,000 validation examples. The improvement in accuracy was less pronounced than with SFT. The suspected reason is that GRPO was applied directly without SFT: the space of outputs that both follow the correct format and receive a reward is too sparse, so there are too few positive samples and the training effect is worse than with SFT. A base model that has not undergone SFT neither understands "answer in the required format" nor understands the task objective. It can only sample randomly and "guess" an answer that both satisfies the format and earns a reward from the enormous space of possible outputs. In GRPO's within-group sampling, an entire group may contain no positive sample, leaving all rewards at zero and causing the gradient signal to nearly disappear. The model naturally struggles to improve.

| -------- | ------------------- | ------------------- | ------------------ |
| baseline | 17.32               | 2.86                | 2.86               |
| grpo     | 25.06               | 13.66               | 13.66              |
